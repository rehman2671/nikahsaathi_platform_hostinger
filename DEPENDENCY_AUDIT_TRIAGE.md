# Dependency Audit Triage

**Audit command:** `pnpm audit --json`

**Captured:** 2026-08-25 (sandbox runtime date)

## Current inventory

The current dependency graph contains 862 resolved dependencies and reports 109 advisories: 3 critical, 37 high, 59 moderate, and 10 low. Direct `axios` and `nanoid` upgrades from the previous remediation were retained and the project still passes typecheck and tests.

## Triage

The highest-risk findings are transitive and span the AWS S3 SDK XML parser (`fast-xml-parser`), the Express 4 dependency chain (`path-to-regexp`/`qs`), the build/tooling chain (`tar`, `rollup`, `vite`, `esbuild`, `picomatch`), and client-side visualization/markdown dependencies (`lodash`, `lodash-es`, `dompurify`, `mdast-util-to-hast`). The graph also reports a high advisory against the installed tRPC release. These cannot be safely resolved with a blanket override without validating the S3 storage helper, Express behavior, Vite/Vitest compatibility, tRPC contracts, and the production build.

## Release decision

This is a **release-blocking security gate**, not an ignored warning. The server should not be exposed to untrusted production traffic until a compatibility-led dependency release updates the AWS SDK/parser chain and the Express/tRPC runtime chain, then reruns `pnpm audit`, typecheck, the full Vitest suite, production build, HTTP security integration tests, and Flutter contract checks. Development-only build-chain advisories must still be isolated from runtime dependencies and removed or formally accepted by the deployment owner.

The project deliberately does not apply a speculative blanket `pnpm.overrides` rule: the repository currently warns that the `pnpm` package field is ignored by the installed pnpm version, and forced transitive versions could silently break the storage or build pipeline. The next dependency release must first migrate package-manager override configuration to the supported format, upgrade direct parents in small groups, and record each remaining advisory path with owner, severity, exploitability, mitigation, and target date.

## Current mitigations

The application already limits request bodies, validates startup configuration, restricts origins and CSRF-protected cookie mutations, verifies Telegram webhook secrets, rate-limits webhook ingress, validates safety regexes, and uses ownership-aware media authorization. These controls reduce exposure but do not replace remediation of vulnerable packages.

### Decision rules

Critical and high runtime-chain findings are release blockers and require a parent-package upgrade or a compensating control approved by Backend & Security. Moderate and low findings require parent-chain review and are not silently suppressed. Re-run the audit after every dependency change and update this ledger with closure evidence or a renewed owner and target date.
